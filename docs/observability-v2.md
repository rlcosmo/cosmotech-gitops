# V2 SQS/Worker reconciliation

`gitops/observability/v2-sqs-workers` contains the byte-identical alert rules and dashboard JSON data from the pinned canonical observability commit in `gitops/releases/v2-sqs-workers-source.json`. Changes to PromQL/dashboard definitions belong in cosmotech-observability first; update this release bundle after its CI passes.

Bootstrap only the two objects from this directory after review/CI and install the `argocd-observability-v2.json` Role/RoleBinding from cosmotech-kubernetes-rbac. The role permits patch/update of those names only; it cannot create or delete objects. Deletion needs deliberate bootstrap again. Then install the two observability-v2 project/application manifests in the management Argo namespace. They use the existing cluster/repository identity. This infrastructure-only project requires the GitHub web-flow merge signature (B5690EEEBB952194) after repository CI/review. Bootstrap imports only its fingerprint-verified public key and appends observability to the existing cluster namespace scope, preserving cluster authentication. The orders-dev project retains its exclusive promotion-authority key and release gates. The observability application runs with automatic self-heal and pruning disabled. No workloads, volumes, namespace, networking or credentials are managed here.

Check Application revision and Synced/Healthy, live PrometheusRule names and manager annotation, then Prometheus `/api/v1/rules` for all eight healthy rules and authenticated Grafana dashboard/datasource requests. Kubernetes reconciliation alone does not certify rule evaluation while Prometheus or Grafana is unavailable.

The dashboard ConfigMap is a versioned source artifact, without the grafana_dashboard sidecar-import label. The existing scoped API publisher retains ownership of the live UID and Lab V2 folder. This prevents duplicate provisioning or moving existing Grafana data; authenticating and validating that dashboard still requires Grafana recovery. The provenance manifest records the original source hash, artifact hash and dashboard-data hash.

The orders delivery workflow triggers only for application manifests or their release receipts. Infrastructure/observability/DR commits run validation and the isolated Argo reconciliation without starting an Orders rollout. Manual delivery remains guarded by the existing signed-publisher verification.
